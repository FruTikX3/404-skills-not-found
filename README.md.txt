Харнесс решает набор задач (search, math, data_analysis, coding) при ограниченном бюджете токенов и времени. Каждая задача оценивается по баллам (reward), и цель харнесса набрать как можно больше баллов.

Основные идеи:
Для каждой задачи считается ожидаемый расход токенов, и задачи запускаются в порядке выгодности: сначала дешёвые группы, внутри группы сначала с большим числом баллов.
Если в условии есть файл, папка или сущность, которых нет в рабочей папке, задача помечается как подозрительная и уходит в конец очереди. Бюджет на неё не тратится, пока она не окажется решаемой.
Большинство задач решаются локальными решателями без обращений к LLM. LLM подключается только для того, что локально не решилось.
Экономить ресурсы. Контекст ограничен, число попыток ограничено, модель выбирается под тип задачи.
Ответ каждой задачи пишется в answer.txt, а общий файл решений обновляется после каждой решённой задачи.

Структура:
obraz_build.bat собирает образ Docker. Вредоносного кода туда не добавляли, файл сделан для удобства.
tasks/ — папка с задачами. Внутри без вложенных папок, каждая задача в своей папке, имена вида search_0022.
scripts/ — основные скрипты.
run_agent.py — сам харнесс.
Как запустить
Запустить obraz_build.bat. Он проверяет Docker и Python, собирает образ.
Положить задачи в tasks/.
Запуск обработки стартует автоматически после сборки.

Параметры харнесса:

Параметр / переменная	Что задаёт
--tasks-dir / TASKS	папка с задачами (по умолчанию /data/tasks)
--budget / TOKEN_BUDGET	бюджет в выходных токенах (по умолчанию 100000)
--out / OUT	куда писать solutions.json; в папке задач он пишется в любом случае
LLM_BASE_URL, LLM_API_KEY	прокси LLM; без них работает только локальная часть
--local-only	только локальные решатели, без обращений к LLM
--workers	число параллельных потоков (до 3)

Общее время работы ограничено 60 минутами (TOTAL_LIMIT_S = 3600), с запасом 60 секунд.

Бюджет

Стоимость считается так: входные токены / 10 + выходные токены. Токены рассуждений считаются как выходные. Задача, которая тратит слишком много, останавливается на потолке, равном 4 оценкам стоимости (для поиска не ниже примерно 1500 единиц).

Результаты
<задача>/answer.txt — ответ решённой задачи.
solutions.json — все ответы одним файлом, обновляется после каждой задачи.
trajectories.jsonl — по строке на задачу: тип, награда, путь (local или llm), расход, решена ли.

Для задач coding в answer.txt записывается полный исправленный модуль.

Локальные решатели
math. Распознаёт типовые формулировки: НОД, НОК, цифровой корень, сумма цифр степени, делители, простые числа, сочетания, упорядоченные пары, Коллатц, системы счисления и другие. Ответ выдаётся, только если формулировка распознана однозначно.
data_analysis. Счётчики и суммы по CSV с фильтрами по продукту, региону и месяцу.
search. Обход kb/*.md по полям вида Ключ: значение, с проверкой цепочек (например, сотрудник → компания → город).
coding. Перебор небольших правок кода, принимается только версия, которая проходит тесты задачи.
